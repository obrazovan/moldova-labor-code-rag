# Отчет по Этапу 5: Генерация ответов через LLM и защита от галлюцинаций

## 1. Обзор этапа

В рамках пятого этапа проекта реализована подсистема генерации юридических ответов на базе языковых моделей **Google Gemini** через официальный SDK `google-genai`. Конвейер обеспечивает строгую привязку к нормам Трудового кодекса Республики Молдова, гарантирует детерминированность вывода, предотвращает фактологические галлюцинации и автоматически формирует блок цитируемых первоисточников.

---

## 2. Архитектурная схема пайплайна

```text
[Пользовательский вопрос]
          │
          ▼
   [SearchPipeline]  ───>  Top-5 отранжированных чанков ТК РМ
          │
          ▼
   [PromptBuilder]   ───>  Форматирование фрагментов: [Фрагмент i | Статья X: Название]
          │                Сборка блока КОНТЕКСТ + ВОПРОС ПОЛЬЗОВАТЕЛЯ
          ▼
   [GeminiClient]    ───>  Системный промпт (роль консультанта + 3 строгих правила)
          │                Параметры: temperature=0.0, max_output_tokens=1024
          │                Retry с экспоненциальным бэкоффом (503/429) + Fallback
          ▼
     [RAGService]    ───>  Готовый ответ: {query, answer, retrieved_docs, sources}
```

## 3. Конфигурация генерации (`configs/generation.json`)

```json
{
  "model_name": "gemini-2.5-flash",
  "temperature": 0.0,
  "max_output_tokens": 1024,
  "system_prompt": "Ты — официальный юридический консультант-ассистент по Трудовому кодексу Республики Молдова.\nТвоя задача — отвечать на вопросы пользователя ИСКЛЮЧИТЕЛЬНО на основе предоставленных фрагментов статей Кодекса в блоке КОНТЕКСТ.\n\nСтрогие правила работы:\n1. Опирайся только на факты, упомянутые в КОНТЕКСТЕ. Категорически запрещено придумывать нормы или домысливать правила из других юрисдикций.\n2. Если в предоставленном контексте нет прямого ответа на вопрос пользователя, ответь строго одной фразой: 'В предоставленном контексте информации недостаточно для ответа на данный вопрос.'\n3. Если ответ найден, в конце текста обязательно сформируй раздел 'Источники:' со списком статей, на которых основан ответ (в формате: 'Статья X. Название статьи')."
}
```

> **Примечание:** Поддерживается переопределение рабочей модели через переменную окружения `GEMINI_MODEL` (например, `GEMINI_MODEL=gemini-3.5-flash` или `gemini-3.8-flash`) в файле `.env`.

## 4. Механизмы защиты от галлюцинаций

1. **Детерминированность генерации (`temperature: 0.0`)**:
   - Полное отключение случайного сэмплирования токенов, что обеспечивает строгую фактологическую точность и воспроизводимость ответов.
2. **Юрисдикционная изоляция (Правило 1)**:
   - Запрет на использование знаний о трудовом праве других государств (РФ, Румынии, ЕС и др.). Модель отвечает строго по предоставленным фрагментам ТК РМ.
3. **Строгий шаблон отказа (Правило 2)**:
   - Если вопрос находится вне предметной области (Out-of-Domain) либо в найденных статьях нет нормы, регламентирующей вопрос, модель возвращает ровно одну стандартную фразу:
   `«В предоставленном контексте информации недостаточно для ответа на данный вопрос.»`
4. **Обязательная атрибуция первоисточников (Правило 3)**:
   - В конце успешного ответа формируется раздел `Источники:` с перечислением статей в формате: `Статья X. Название статьи`.

## 5. Реализованные модули в пакете `src/generation/`

### 5.1. `src/generation/llm_client.py` (`GeminiClient`)
- **Официальный SDK**: Работа через `google.genai.Client`.
- **Проверка ключа API**: Информативное исключение `ValueError`, если `GEMINI_API_KEY` не задан в `.env`.
- **Отказоустойчивость**:
  - Экспоненциальный бэкофф при ошибках сети и лимитов (HTTP 503 UNAVAILABLE, 429 RESOURCE_EXHAUSTED).
  - Интеллектуальный fallback между версиями Flash при временных пиковых нагрузках Google API.

### 5.2. `src/generation/prompt_builder.py` (`PromptBuilder`)
- **Метод `build_context(documents)`**: Формирует чистый контекст с явными границами:
  ```text
  [Фрагмент 1 | Статья 113: Продолжительность ежегодного оплачиваемого отпуска]
  {текст статьи}
  ```
- **Метод `build_user_message(query, documents)`**: Объединяет размеченный `КОНТЕКСТ` и `ВОПРОС ПОЛЬЗОВАТЕЛЯ`.
- **Метод `extract_sources_from_docs(documents)`**: Извлекает структурированный список уникальных статей.

### 5.3. `src/generation/rag_service.py` (`RAGService`)
- Сквозной сервис, соединяющий `SearchPipeline` -> `PromptBuilder` -> `GeminiClient`.
- Метод `answer(query: str) -> dict` возвращает словарь с полями:
  - `query`: текст вопроса
  - `answer`: сгенерированный LLM ответ
  - `retrieved_docs`: список документов, переданных в контекст
  - `sources`: извлеченные источники статей

## 6. Результаты тестовых запусков

### Тест 1 (Полноценный вопрос по ТК РМ):
- **Вопрос**: `«Какова продолжительность ежегодного оплачиваемого отпуска?»`
- **Ожидание**: Извлечение Статьи 113 и точный ответ о 28 календарных днях с указанием источника.
- **Время ответа**: `5.51 сек`
- **Сгенерированный ответ**:
  > Согласно предоставленному контексту, продолжительность ежегодного оплачиваемого отпуска составляет:
  >
  > 1. **Для всех работников** — не менее 28 календарных дней ежегодно, без учета нерабочих праздничных дней.
  > 2. **Для работников отдельных отраслей национальной экономики** (таких как образование, здравоохранение, государственная служба и др.) — органическим законом может быть установлена иная продолжительность ежегодного оплачиваемого отпуска (исчисляемая в календарных днях).
  >
  > **Источники:**
  > Статья 113. Продолжительность ежегодного оплачиваемого отпуска
- **Извлеченные источники**:
  - `Статья 113. Продолжительность ежегодного оплачиваемого отпуска`
