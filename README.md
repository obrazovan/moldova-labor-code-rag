# Moldova Labor Code RAG (RAG-система по Трудовому кодексу Молдовы)

Модульная Retrieval-Augmented Generation (RAG) система по законодательству Республики Молдова (Трудовой кодекс), реализованная на чистом Python без тяжелых фреймворков (LangChain / LlamaIndex).

## Стек технологий и архитектура

- **Язык**: Python 3.10+
- **Векторная БД**: ChromaDB (локальное хранилище)
- **Эмбеддинги**: Sentence-Transformers (легкие модели для CPU: `rubert-tiny2` / `bge`)
- **Reranker**: FlashRank / Cross-Encoder (локально на CPU)
- **LLM**: Google Gemini Flash через официальный API
- **Архитектура**: Чистый модульный пайплайн с разделением ответственности:
  - `src/grabber/` — Сбор и дедупликация нормативных документов
  - `src/preprocessing/` — Парсинг HTML, очистка структуры и чанкинг по статьям
  - `src/embeddings/` — Векторизация и управление векторным индексом
  - `src/retrieval/` — Семантический поиск и фильтрация
  - `src/reranking/` — Переранжирование кандидатов
  - `src/generation/` — Формирование контекста и вызов LLM с защитой от галлюцинаций
  - `src/evaluation/` — Набор тестов и метрики качества (Hit Rate, MRR)

## Этап 1: Сбор данных (Grabber)

В рамках первого этапа реализован отказоустойчивый модуль автоматического сбора данных с государственного портала [legis.md](https://www.legis.md/):
- **Управление языковой сессией**: Автоматическая инициализация сессии через `https://www.legis.md/languages/index/ru` с сохранением cookie (`ci_session`) для получения актуального текста кодекса на русском языке.
- **Сборка полного документа**: Корректное объединение базовой разметки и динамически подгружаемого тела акта (`showdetails/{doc_id}`).
- **Стабилизация хеша**: Очистка динамических токенов Cloudflare (`__CF$cv$params`), гарантирующая детерминированный SHA-256 хеш.
- **Дедупликация**: Проверка SHA-256 по `data/raw/manifest.json`. Если нормативный акт не изменялся, повторное скачивание пропускается.
- **Метаданные**: Фиксация даты загрузки, URL и контрольной суммы в `metadata.json`.

## Этап 2: Предобработка и чанкинг данных (Preprocessing & Chunking)

В рамках второго этапа реализован модульный конвейер предварительной обработки и многостратегического чанкинга нормативного текста:

### 1. Очистка HTML (`src/preprocessing/cleaner.py`)
- **Извлечение контента**: Поиск основного контейнера документа (`div#contentdoc.doc`) с помощью `BeautifulSoup`.
- **Удаление служебных блоков**: Декомпозиция тегов `<script>`, `<style>`, `<button>`, `<form>`, `<nav>`, `<header>`, `<footer>`, `<iframe>` и элементов интерфейса (попапы, модалки, кнопки печати, логотипы).
- **Сохранение надстрочных индексов (`<sup>`)**: Преобразование тегов `<sup>` в формат `^{...}` (например, `Статья 7<sup>1</sup>` $\rightarrow$ `Статья 7^1`, пункты вида `b^1`), что исключает коллизии и склеивание статей с обычными номерами (например, исключает смешение статей `7^1` и `71`).
- **Нормализация символов**: Замена неразрывных пробелов `\xa0` и `\u200b` на стандартные пробелы, схлопывание множественных пробелов и нормализация избыточных переводов строк (`\n{3,}` $\rightarrow$ `\n\n`).

### 2. Синтаксический анализ структуры (`src/preprocessing/parser.py`)
- **Извлечение иерархии через RegEx**: Выделение разделов (`^РАЗДЕЛ\s+[IVXLCDM\d]+`), глав (`^Глава\s+[IVXLCDM\d]+`) и статей (`^Статья\s+\d+...`).
- **Склеивание многострочных заголовков**: Обработка переносов строк в заголовках статей и разделов, возникших при конвертации из Word в HTML.
- **Полнота извлечения**: Извлечены **14 разделов**, **66 глав** и **430 статей** кодекса без коллизий и потерь.
- **Атрибуты статьи**: Каждая статья содержит `number` (номер), `title` (заголовок), `text` (полный текст статьи), `body` (тело статьи без заголовка), `paragraphs` (список отдельных абзацев/пунктов), `section` (раздел) и `chapter` (глава).

### 3. Стратегии чанкинга (`src/preprocessing/chunker.py`)

Класс `TextChunker` реализует 4 стратегии разбиения текста:

| Стратегия | Параметры | Описание |
|---|---|---|
| **by_article** | — | Статья целиком является одним чанком. Основной рабочий набор для юридического RAG. |
| **fixed_size** | `chunk_size=500` | Нарезка текста статьи фиксированными блоками по 500 символов. |
| **fixed_overlap** | `chunk_size=500`, `overlap=100` | Нарезка блоками по 500 символов с нахлестом 100 символов (шаг 400 символов). |
| **by_paragraph** | — | Разбиение статьи по отдельным абзацам и пунктам (`paragraphs`). |

### 4. Структура метаданных чанка

Каждый чанк содержит уникальный детерминированный `chunk_id` и структурированные метаданные:

```json
{
  "chunk_id": "codul_muncii_by_article_art_1",
  "text": "Статья 1. Основные понятия\n\nВ настоящем кодексе следующие основные понятия используются в значении:\n...",
  "source": "codul_muncii",
  "url": "https://www.legis.md/cautare/getResults?doc_id=155882&lang=ru",
  "title": "Основные понятия",
  "section": "РАЗДЕЛ I. ОБЩИЕ ПОЛОЖЕНИЯ",
  "document_id": "codul_muncii",
  "updated_at": "2026-09-14T20:22:22.422099+00:00",
  "chunk_strategy": "by_article",
  "metadata": {
    "source": "codul_muncii",
    "url": "https://www.legis.md/cautare/getResults?doc_id=155882&lang=ru",
    "title": "Основные понятия",
    "section": "РАЗДЕЛ I. ОБЩИЕ ПОЛОЖЕНИЯ",
    "chapter": "Глава I. ВВОДНЫЕ ПОЛОЖЕНИЯ",
    "document_id": "codul_muncii",
    "updated_at": "2026-09-14T20:22:22.422099+00:00",
    "chunk_strategy": "by_article",
    "article_number": "1",
    "chunk_index": 0
  }
}
```


## Установка и запуск

### 1. Клонирование репозитория
```bash
git clone https://github.com/obrazovan/moldova-labor-code-rag.git
cd moldova-labor-code-rag
```

### 2. Создание виртуального окружения
```bash
python -m venv venv

# Windows (PowerShell):
.\venv\Scripts\Activate.ps1

# Linux / macOS:
source venv/bin/activate
```

### 3. Установка зависимостей
```bash
pip install -r requirements.txt
```

### 4. Запуск сбора данных (Этап 1: Grabber)
```bash
python -m src.grabber.legis_grabber
```

### 5. Запуск предобработки и чанкинга (Этап 2: Pipeline)
```bash
python -m src.preprocessing.pipeline
```
